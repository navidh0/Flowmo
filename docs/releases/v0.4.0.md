# Flowdo 0.4.0 — Linux, and automatic updates

**Flowdo is on Linux now.** Alongside the Windows installer and portable build, this release ships an AppImage (`Flowdo-0.4.0.AppImage`) and a `.deb` package (`flowdo_0.4.0_amd64.deb`). "Launch at login" in Settings → System works there too. Global hotkeys are unavailable under Wayland — the app tells you rather than accepting a binding that will never fire.

**Flowdo updates itself now.** The Windows installer and the Linux AppImage check GitHub Releases when Flowdo starts and every 6 hours after, download the update in the background, and install it the next time Flowdo restarts — never in the middle of a running session. Settings → Updates shows your current version and status, with "Check for updates" and, once a download is ready, "Restart to update." A toggle turns automatic checking off if you'd rather update manually.

The portable Windows build and the `.deb` package don't update themselves — Settings says so for each and links to the releases page instead.

**One manual step if you're coming from 0.3.x.** This is the first version with the updater, so it has nothing to update *from* — you'll need to install 0.4.0 yourself, the same way as always. Every version after this one should offer to update automatically.

## Installing on Linux

**AppImage:**

```
chmod +x Flowdo-0.4.0.AppImage
./Flowdo-0.4.0.AppImage
```

**deb:**

```
sudo apt install ./flowdo_0.4.0_amd64.deb
```

**Your data** stays in `~/.config/Flowdo` on Linux, `%APPDATA%\Flowdo` on Windows. Updating does not touch it, and uninstalling does not delete it.

**These builds are unsigned**, same as Windows. On Windows, SmartScreen will show "Windows protected your PC" — choose **More info**, then **Run anyway**. The AppImage and `.deb` are unsigned too; most Linux setups won't warn about that, but it's worth knowing if a package manager or AppImage launcher does flag it.

## Behind the scenes

Every change now goes through a stricter automated gate before it can merge or release — typecheck, the full test suite, a real build, and an end-to-end run, on Windows and Linux both, plus checks that catch things like accidental hard-coded colors or process-boundary violations. Nothing user-facing here, just fewer ways for a regression to slip through.
